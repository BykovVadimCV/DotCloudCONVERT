# DotCloudCONVERT

Конвертер E57 → 2D растровый план. Сейчас в репозитории первый этап — **`simscan`**,
синтезатор наборов данных: процедурные этажи, виртуальное сканирование наземным сканером
(Open3D), запись E57 со станциями и позами через pye57 и точный эталон плана.

Разбор ТЗ, с чем согласен и с чем нет, и план по этапам — [docs/ANALYSIS.md](docs/ANALYSIS.md).

## Установка

```bash
python -m venv .venv && . .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
# только Linux без графики (Colab, сервер, CI): Open3D нужна libEGL
sudo apt install libegl1
```

## Запуск

```bash
python -m simscan generate --out D:/synth --count 200 --seed 0 --workers 2
python -m simscan generate --out D:/synth --count 1 --set scanner.angular_step_deg=0.3
python -m simscan dump-config > my.yaml           # все параметры; правка и --config my.yaml
python -m simscan assets --source gso --out D:/scans --per-role 40   # реальные сканы предметов
python -m simscan generate --out D:/synth --count 200 --set interior.scan_dir=D:/scans
python -m simscan pair D:/synth/scene_00000 D:/synth/scene_00001 --out pairs.png   # сетка пар
```

Одна сцена (4–8 станций по 3,75 млн лучей при шаге 0,12°) — 20–60 с и 100–250 МБ E57.
Для обучения 2D-модели шаг 0,2–0,25° обычно достаточен и в 3–4 раза быстрее.
Одна и та же пара `(seed, номер сцены)` всегда даёт ту же сцену.

## Планировки

По умолчанию (`layout.source: apartment`) — генератор квартир `simscan/apartment.py`:
выращивание комнат на сетке по методу Lopes et al. 2010 в реализации ProcTHOR (Apache-2.0,
см. NOTICE), доработанное под квартиры секционного дома: фасад(ы) с окнами, глухие
межквартирные стены, вход в прихожую с лестничной клетки, санузлы в глубине, лоджии,
несущая внутренняя стена, проверки формы и достижимости. Другие источники:
`simscan` (простое BSP-разбиение) и `datasetgen` (ReFloorBRUSNIKA, ниже).

```bash
python -m simscan plans --out D:/plans --count 12        # только планы + рендер, ~1-3 с на план
python -m simscan render D:/synth/scene_00001            # plan.png для готовой сцены
```

Ограничение: 3- и 4-комнатные пока строятся редко (у них малый вес в программе),
стабильно - студии, 1- и 2-комнатные.

## Реалистичность сцены и сканера

Blender в цепочке не используется: при LiDAR-симуляции он тоже трассирует лучи (BlAInder -
`BVHTree.ray_cast` по одному лучу из Python), а реализм определяется не движком, а тем,
**что стоит в сцене** и **как моделируется луч**.

**A. Сцена** (`interior.py`, `furniture.py`, `realism.py`)
- мебель из частей: ножки, сиденья, спинки, сквозные стеллажи с книгами, кровати на ножках,
  цоколи шкафов и кухни, растения, вешалки - лучи проходят под и между частями;
- шторы (складки) и тюль (пропускает 40-80 % лучей), дверные коробки и наличники,
  стояки в санузлах (трубы или короб), секционные радиаторы, светильники, ТВ и картины на стенах;
- неидеальные стены: гладкое случайное поле неровности (СКО 1-4 мм, корреляция 0,4-1,2 м),
  завал от вертикали до 3 мм/м, отклонение углов от 90° (сдвиг плана, учитывается в эталоне),
  фактические толщины ±5 мм. Деформация непрерывная - оболочка остаётся замкнутой;
- беспорядок (`interior.mess`, уровень 0..1 на сцену): куртки и пледы, наброшенные на коробки,
  спинки стульев, диваны и кровати (ткань свисает за край опоры, складки), одежда на крючках и
  вешалках, сумки и кучи белья, стопки коробок, доски и листы у стены. Это сетки, а не
  параллелепипеды, класс `clutter`;
- реальные сканы предметов (`interior.scan_dir`): Google Scanned Objects - 1033 бытовых предмета,
  отсканированных Google (обувь, сумки, игрушки, посуда, коробки, техника), в метрах.
  Ставятся в натуральную величину: обувь парами в прихожей, вещи на столах, тумбах и полках,
  сумки и игрушки на полу. `python -m simscan assets --source gso` качает их из публичного
  бакета Kubric, упрощает до 3000 треугольников и раскладывает по ролям
  (`shoes/`, `tabletop/`, `floor/`); 40 на роль - около 10 МБ;
- внешние модели мебели: `interior.asset_dir` = каталог `<вид>/*.obj|glb|ply|stl` - предмет
  вписывается в габарит процедурного. Загрузчики `--source polyhaven` (CC0) и
  `--source objaverse` (CC0 / CC BY / CC BY-SA, нужен `pip install objaverse`) написаны,
  но в среде разработки не проверены (сайты закрыты прокси) - сначала прогоните на 2-3 моделях.

Лицензии: GSO - CC BY-SA 4.0, загрузчик пишет `ATTRIBUTION.csv` (что, откуда, автор, лицензия).
Обучение на облаках, отрисованных из этих моделей, лицензию не нарушает; сами OBJ
распространять только вместе с атрибуцией и на тех же условиях. Наборы с лицензией
«только некоммерческое» (3D-FUTURE, ScanNet, Matterport3D) для фирмы не годятся.

**B. Сканер** (`scanner.py`)
- модель пятна луча (по мотивам HELIOS++): на кромках луч - 15 подлучей гауссова профиля
  (выходной диаметр + расходимость); ответ - эхо с наибольшей энергией, дальность внутри эха -
  средняя по энергии. Эхо ближе `echo_separation_m` сливаются (смешанный пиксель), дальше -
  выбирается одно: «хвостов» через всю комнату нет;
- шум дальности растёт с углом падения (~ sec, Soudarissanane 2011) и с растяжением пятна
  на наклонной поверхности; слабый отклик (тёмное, далеко, частичное пятно) - пропуск;
- тюль и стекло пропускают часть лучей.

Отладка: `python -m simscan debug <сцена>` или `--set export.debug=true` при генерации -
в `<сцена>/debug/`: панорама станции (дальность, классы, кромки, смешанные эхо, пропуски,
интенсивность), срез у кромки «центральный луч / модель пятна», неровность стены,
шум и пропуски от угла падения, галерея мебели, галерея беспорядка и он же глазами сканера,
`stats.json`.

## Обучающая пара

Вход сети - не облако, а псевдочертёж, который строится из облака без нейросети
(`rasterize.py`, раздел 5.5 ТЗ): по каждой станции - докуда лучи долетели до пола и
потолка (полярные корзины по 0,5°), объединение = свободное пространство; закрытие 0,6 м
даёт здание, внутренние стены = здание минус свободное, наружные - кольцо 0,4 м; дыры шире
0,6 м - «не отсканировано»; где лучи ушли за стену - признак окна. Цель - `gt/unet_mask.png`
(0 / 64 стена / 128 окно / 192 дверь) в том же кадре, пиксель в пиксель.

```
input/free_space.png   вход: белое - свободно, чёрное - стена, серое 140 - признак окна,
                       светло-серое 215 - не отсканировано (3 одинаковых канала, как RGB чертежа)
input/valid.png        где скан что-то видел; вне её эталон есть, а данных нет - маска потерь
input/input.json       IoU / точность / полнота стен входа против эталона (базовая линия без сети)
input/pair.png         (export.debug или `simscan pair`) облако | вход | эталон | разница стен
```

Входная картинка без сети совпадает с эталоном по стенам на IoU 0,4-0,5: наружные стены
к соседям тоньше, чем принятые 0,4 м, шкафы до потолка и тени за углами выглядят как стены,
неотсканированные комнаты пустые. Это и есть работа сети.

## Пресеты сканера Leica BLK360

```bash
python -m simscan generate --out D:/synth --count 200 --config configs/blk360_g2.yaml
```

| | `blk360_g1.yaml` (2016) | `blk360_g2.yaml` (2022) |
|---|---|---|
| Дальность | 0,6–60 м | 0,5–45 м |
| Поле зрения по вертикали | 300° (угол места −60…+90) | 270° (−45…+90, слепой конус под сканером) |
| Режимы шага на 10 м | 5 / 10 / 20 мм | 6 / 12 / 25 / 50 мм |

Дальность, поле зрения и шаг взяты из спецификаций Leica. Модель шума подобрана под эти цифры и
с реальным сканом не сверена.

## Планировки из datasetgen (ReFloorBRUSNIKA)

```bash
pip install shapely networkx pydantic           # зависимости datasetgen
python -m simscan generate --out D:/synth --count 200 --config configs/blk360_g2.yaml \
    --set layout.source=datasetgen --set layout.datasetgen_path=D:/ReFloorBRUSNIKA/datasetgen
```

`simscan/datasetgen_adapter.py` берёт из datasetgen только геометрию (стратегия планировки + балконы,
без рендера) и переводит её в `Layout`:
- px → м по длинной стороне здания (`layout.datasetgen_long_side_m`, по умолчанию 8–16 м);
- толщины стен разыгрываются заново в метрах (в datasetgen это 3–200 px без физического смысла);
  тонкие перегородки datasetgen остаются тонкими (≤ 0,12 м);
- помещения — связные области между стенами (прямоугольники комнат datasetgen используются только
  для типа: кухня, санузел, коридор, балкон);
- ограждение балкона — стена 1,0–1,1 м, стена балкона — с балконным блоком (дверь + окно);
- двери и окна ставятся заново, с высотами: в datasetgen их нет в данных, только в растре.

Стратегии `bsp` и `voronoi` по умолчанию выключены (`layout.datasetgen_strategies`): у первой комнаты
покрывают ~30 % контура, у второй нет внутренних стен.

## Что лежит в каталоге сцены

```
scene_00042/
  scan.e57               скан на станцию: точки в СК станции, поза (кватернион + перенос) в заголовке,
                         intensity, rowIndex/columnIndex, лучи без отклика с cartesianInvalidState = 1
  scan_merged.e57        (export.write_merged) то же облако одним сканом — режим «без станций»
  labels/scan_000.npz    метки точек в порядке записи в E57: label, instance, virtual, mixed, valid, row, col
  gt/walls.png           маски на секущей плоскости 1,25 м (0/255), мм/пикс = export.pixel_mm
  gt/doors.png, gt/windows.png
  gt/rooms.png           uint16: номер помещения + 1
  gt/classes.png         0 фон, 1 стена, 2 дверь, 3 окно
  gt/plan_gt.png         «чертёжный» вид: стены чёрные, окна серые
  gt/unet_mask.png       маска в формате U-Net ReFloorBRUSNIKA: 0 фон, 64 стена, 128 окно, 192 дверь
                         (проём + полотно); квадратный кадр, наружная стена = 30 px, как в core/scale_norm.py
  gt/gt.json             привязка растра, стены (грани, толщины в мм), проёмы (ширины в мм, закрыта ли дверь),
                         площади помещений, позы станций, layout → СК объекта
  layout.json            планировка целиком, станции, позы истинные и записанные, параметры эффектов, конфиг
  input/free_space.png   вход сети (псевдочертёж по свободному пространству), input/valid.png - маска потерь
  preview.png            точки полосы 1,0–1,5 м, прочитанные из scan.e57, поверх эталона
  mesh.ply               (export.write_mesh) сетка сцены, цвет = класс
```

Метки точек для скана `i` сопоставляются с тем, что вернёт pye57:
`read_scan(i, ignore_missing_fields=True)` отдаёт точки с `valid == True` в том же порядке, то есть
`label[valid]`. Классы — в `simscan/labels.py`. `virtual` — точка из отражения в зеркале (лежит за стеной),
`mixed` — смешанный пиксель на кромке.

Привязка пикселя эталона, как в конвертере:
`x = origin_x + (j + 0.5) * px`, `y = origin_y + (H - 1 - i + 0.5) * px` в СК планировки,
затем `world = Rz(yaw) * layout + offset` (`gt.json → layout_to_world`).

## Подключение своей планировки

`Layout` (`simscan/layout.py`) — стены осями с толщиной, проёмы на стенах, помещения, предметы.
Внешний генератор (например, `datasetgen`) достаточно перевести в этот словарь
(`Layout.from_dict`) — дальше сцена, сканирование и эталон работают без изменений.

## Эффекты сканера

Каждый включается флагом в `effects` (конфиг), параметры разыгрываются на сцену из диапазонов
и сохраняются в `layout.json → meta.effects_sampled`:

| Флаг | Что делает |
|---|---|
| `range_noise` | шум дальности σ = (σ₀ + k·r)·√(0,5 / отражательная способность) |
| `mixed_pixels` | точки между передним и задним планом у перепадов глубины |
| `grazing_dropout` | пропуски при скользящем падении (75…89°) |
| `low_signal_dropout` | пропуски на тёмных и далёких поверхностях |
| `glass` | луч проходит стекло с вероятностью p, иначе редкий отклик от стекла |
| `mirrors` | отражённый луч, точка за зеркалом на суммарной дальности |
| `registration_error` | записанная поза станции (кроме первой) с ошибкой 1–4 мм и 0,002–0,02° |
| `people` | люди, свои на каждой станции |
| `keep_invalid` | лучи без отклика пишутся направлением с InvalidState = 1 |

Параметры сканера и шума — стартовые, с паспортами конкретных сканеров не сверены.
